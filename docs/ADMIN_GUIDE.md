# คู่มือใช้งานสำหรับ Admin

## 1. ตั้งค่า Admin คนแรก

ดูขั้นตอนเต็มใน [`../README.md`](../README.md#6-สร้าง-admin-คนแรก) — สรุปคือรัน `npm run prisma:seed` แล้วเปลี่ยน PIN ของบัญชีตัวอย่าง `ADM001` ทันที หรือสร้าง Admin ใหม่แล้วปิดใช้งานบัญชีตัวอย่างทิ้ง

## 2. จัดการผู้ใช้งาน (เมนู "ผู้ใช้งาน")

### สร้างผู้ใช้ใหม่
1. กด "+ สร้างผู้ใช้ใหม่"
2. กรอกรหัสพนักงาน, ชื่อ-นามสกุล, เลือก Role (`operator` / `engineer` / `admin`), ตั้ง PIN เริ่มต้น (4–12 หลัก), อีเมล (ถ้าต้องการรับแจ้งเตือน)
3. กด "บันทึก" — แจ้งรหัสพนักงาน + PIN เริ่มต้นให้พนักงานเปลี่ยนเองครั้งแรกที่ login

### รีเซ็ต PIN
กดปุ่ม "Reset PIN" ที่แถวของผู้ใช้ → กรอก PIN ใหม่ → ระบบจะบังคับให้ทุก session เดิมของผู้ใช้นั้น logout ทันที (ต้อง login ใหม่)

### ปิด/เปิดใช้งานผู้ใช้
กดปุ่ม "ปิดใช้งาน" เมื่อพนักงานลาออก/โอนย้าย — บัญชีที่ถูกปิดใช้งานจะ login ไม่ได้ทันที และ token เดิมที่ค้างอยู่จะถูก revoke ด้วย

## 3. จัดการพิกัด GPS / Geofence (เมนู "พิกัด/Geofence")

**สำคัญที่สุด**: ต้องตั้งพิกัดจริงของหัวสายพานทั้ง 11 หัวก่อนเปิดใช้งานจริง เพราะพิกัดตัวอย่างจาก seed script เป็นค่าสมมติ

วิธีตั้งพิกัดแม่นยำที่สุด:
1. เดินไปยืน ณ ตำแหน่งจริงของหัวสายพานนั้น
2. เปิดหน้า "พิกัด/Geofence" บนมือถือ → กด "แก้ไข" ที่หัวสายพานนั้น
3. กด "ใช้ตำแหน่งปัจจุบันของอุปกรณ์นี้" — ระบบจะดึงพิกัด GPS ของอุปกรณ์มาใส่ให้อัตโนมัติ
4. ตั้ง **รัศมี** (เมตร) ตามความเหมาะสมของพื้นที่จริง (ค่าเริ่มต้น 50 เมตร — ปรับตามภูมิประเทศ เช่น พื้นที่โล่งอาจใช้รัศมีแคบลง พื้นที่มีสิ่งกีดขวางสัญญาณ GPS อาจต้องขยายรัศมีขึ้นเล็กน้อย)
5. กด "บันทึก"

ค่านี้จะถูกใช้ร่วมกันโดยมือถือ Operator ทุกเครื่องทันที (ไม่ต้องอัปเดตแอปแต่ละเครื่อง)

## 4. ตรวจสอบ Audit Log (เมนู "Audit Log")

บันทึกทุกเหตุการณ์สำคัญ: login สำเร็จ/ไม่สำเร็จ, การตั้ง/แก้ไขพิกัด, ผลตรวจ geofence, การเริ่ม/ส่งผลตรวจ, การสร้าง/แก้ไขผู้ใช้, การ export รายงาน — กรองตามประเภทเหตุการณ์ได้จาก dropdown ด้านบน

ใช้สำหรับตรวจสอบย้อนหลังกรณีมีข้อสงสัย เช่น พนักงานอ้างว่าตรวจแล้วแต่ไม่มีข้อมูล หรือสงสัยการ mock GPS

## 5. รายการตรวจมาตรฐาน (Checklist Items)

รายการตรวจ 17 รายการต่อหัวสายพาน (Drive Unit 1–4 × 2 รายการ, Belt Cleaner Primary/Secondary, Impact Carry Return, ฝุ่นที่ Chute, สภาพสายพาน, Pulley Primary/Secondary/Take-up/Tail, ดินที่ Cross Bar) ถูกกำหนดไว้ในฐานข้อมูลกลาง (`checklist_item_defs` table) ใช้ร่วมกันทุกหัวสายพานอัตโนมัติ

การแก้ไขเกณฑ์ threshold (เช่น ระดับน้ำมันขั้นต่ำ/สูงสุด) ปัจจุบันทำผ่านฐานข้อมูลโดยตรงหรือ Prisma Studio (`npx prisma studio`) — หากต้องการหน้าจอ Admin สำหรับแก้ไข checklist item ในเวอร์ชันถัดไป สามารถต่อยอดจาก endpoint `/api/v1/checklist-items` ที่มีอยู่แล้ว

## 6. แจ้งเตือน Email/LINE

ตั้งค่าใน `.env` (`SMTP_*`, `ALERT_EMAIL_RECIPIENTS`, `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_ALERT_GROUP_ID`) — ดู [`ENV_VARS.md`](./ENV_VARS.md) การเปลี่ยนค่าต้อง restart backend container (`docker compose restart backend`)

## 7. ข้อจำกัดด้าน GPS Spoofing และคำแนะนำ MDM

ดูรายละเอียดเต็มที่ [`GPS_SPOOFING_AND_MDM.md`](./GPS_SPOOFING_AND_MDM.md) — สรุปสั้น: ระบบตรวจสอบ GPS accuracy และ geofence ที่ server ทุกครั้ง แต่ **ไม่สามารถพิสูจน์ 100% ว่าพิกัดที่รายงานมาไม่ได้มาจากแอป mock GPS** บนอุปกรณ์ที่เปิด Developer Options — แนะนำให้ใช้ MDM (Mobile Device Management) บังคับใช้กับมือถือองค์กรเพื่อลดความเสี่ยงนี้
